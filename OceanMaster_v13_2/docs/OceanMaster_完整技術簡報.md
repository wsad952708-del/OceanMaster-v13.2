## 三、第一層——物理海洋演算法

### 3.1 SST 鋒面偵測（三法融合）

**檔案**：`algorithms.py` L28-106  
**科學原理**：冷暖水交界處（鋒面）是浮游生物和魚群聚集的主要位置。

三種方法融合：

| 方法 | 原理 | 參數 |
|------|------|------|
| **Sobel 梯度** | 計算 2D 空間梯度幅值 `√(Gx²+Gy²)` | 轉換為 °C/km |
| **Cayula-Cornillon (1992)** | 32×32 窗口直方圖雙峰分析 | `delta_t=0.45°C`, `var_ratio=0.76` |
| **Canny 邊緣偵測** | 高斯平滑→梯度→非極大值抑制→雙閾值 | `σ=1.5`, `low=0.3`, `high=0.7` |

**融合策略**：三法投票，≥2 種方法同意 = 鋒面。  
**鋒面強度**：`front_strength = votes / 3`（0-1 連續值）

```
Cayula-Cornillon 核心判定公式：
  between_var = (N_left × N_right / N_total²) × (μ_left - μ_right)²
  ratio = between_var / within_var
  判定條件：ratio > 0.76 且 |μ_left - μ_right| > 0.45°C
```

### 3.2 Chl-a 鋒面偵測（Belkin-O'Reilly 2009）

**檔案**：`algorithms.py` L426-462, L753-868  
**原理**：葉綠素梯度鋒面 = 食物鏈起點。SST 鋒面 ∩ CHL 鋒面 = 最強漁場信號。

```
步驟：
  1. Chl 取 log10（因為分佈高度偏態）
  2. 中值濾波 3×3（保護鋒面形狀，不像 Gaussian 會模糊）
  3. Sobel 梯度 → 閾值 = P85 百分位
```

### 3.3 生產力鋒面（SST + CHL 融合）

**檔案**：`algorithms.py` L633-682  
**公式**：
```
productivity = 0.6 × √(SST_front × CHL_front) + 0.4 × (w_sst × SST_front + w_chl × CHL_front)
```
幾何平均確保兩者都強才給高分，線性項允許某一方特別強也有信號。

### 3.4 FTLE 拉格朗日相干結構

**檔案**：`algorithms.py` L206-325  
**原理**：追蹤海水粒子的移動路徑，找出「吸引脊線」= 浮游生物和餌料被海流聚集的隱形線。

```
演算法：
  1. 在每個格點放虛擬粒子
  2. 用 RK4（四階 Runge-Kutta）積分 3 天（dt=6h）
  3. 計算位移場的 Jacobian 矩陣
  4. 建構 Cauchy-Green 張量 C = JᵀJ
     C₁₁ = (∂Δx/∂x₀)² + (∂Δy/∂x₀)²
     C₁₂ = ∂Δx/∂x₀·∂Δx/∂y₀ + ∂Δy/∂x₀·∂Δy/∂y₀
     C₂₂ = (∂Δx/∂y₀)² + (∂Δy/∂y₀)²
  5. λ_max = 最大特徵值
  6. FTLE = ln(√λ_max) / T
  7. 脊線 = FTLE > P90 百分位
```

### 3.5 渦旋動能 EKE（地轉近似）

**檔案**：`algorithms.py` L469-577  
**物理公式**：
```
  f = 2Ω·sin(φ)              — Coriolis 參數
  dx = R·cos(φ)·Δλ           — 經度真實距離
  dy = R·Δφ                  — 緯度真實距離
  u_g = -(g/f)·∂SSH/∂y       — 地轉流 u 分量
  v_g =  (g/f)·∂SSH/∂x       — 地轉流 v 分量
  EKE = 0.5·(u_g² + v_g²)    — 渦旋動能 (m²/s²)
```

暖渦旋：SSH > +5cm → 反氣旋  
冷渦旋：SSH < -5cm → 氣旋

### 3.6 溫躍層與 D20 計算

**檔案**：`algorithms.py` L332-419  
```
  溫躍層深度 = max(|∂T/∂z|) 的深度
  D20 = 20°C 等溫線深度（線性插值）
  MLD = 表層溫度下降 0.5°C 的深度
```
大目鮪白天躲在溫躍層下方（300-500m），鉤子要下在這裡。

### 3.7 Okubo-Weiss 形變分析

**檔案**：`okubo_weiss.py`（138 行）
```
  W = s_n² + s_s² - ω²
  s_n = ∂u/∂x - ∂v/∂y (法向應變)
  s_s = ∂v/∂x + ∂u/∂y (剪切應變)
  ω = ∂v/∂x - ∂u/∂y (渦度)
  
  W < 0 → 渦旋核心（旋轉主導）
  W > 0 → 應變帶（拉伸主導 → 物質聚集）
```

## 四、第二層——棲地適合度 HSI

### 4.1 核心公式

**檔案**：`hsi_models.py`（623 行）

每個環境因子的適合度指數 (SI) 用**高斯分佈**：
```
  SI(x) = exp(-(x - μ_optimal)² / (2σ²))
```

多因子合併用**加權幾何平均**（比算術平均更嚴格）：
```
  HSI = ∏ SI_i^(w_i / Σw)
```
任何一個因子太差會大幅拉低整體分數。

## 七、第三層——AI 融合引擎

**檔案**：`ai_fusion.py`（560 行）

### 7.1 融合公式

```
最終分數 = HSI × (1 + bonus)
         → max-normalize → [0, 1]
         → percentile rescale → [0.15, 0.95]
         → 2D Gaussian 空間平滑 (σ=2.0 鮪魚, σ=1.0 魷魚)
```

### 7.2 Bonus 加分項（已從程式碼提取）

| 來源 | 加分比例 | 觸發條件 |
|------|---------|---------|
| SST 鋒面 | +20% | `front_strength > 0` |
| 鋒面持久性 | +10% | `front_persistence > 0` |
| FTLE 脊線 | +15% | normalize 後加權 |
| 海流匯聚帶 | +10% | `convergence_index > 0` |
| VIIRS 漁船燈光 | +25% | 高斯熱力圖 |
| 風-鋒面位移 | +8% | 5≤wind≤15 m/s 且有鋒面 |
| GFW 漁撈密度 | +15% | AIS 漁船在此作業 |
| 高風速懲罰 | -15% | wind > 15 m/s（線性衰減） |

**Bonus 上下限**：`clip(-0.30, +0.75)`

### 7.3 Percentile Rescaling（當日相對排名）

```python
p5, p95 = percentile(scores, [5, 95])
scaled = 0.15 + (score - p5) / (p95 - p5) × (0.95 - 0.15)
# 上限 0.95：沒有任何漁場條件是 100% 完美的
```

> **⚠️ 重要設計限制揭露**：
> Percentile rescaling 代表輸出分數是**當日海域內的相對排名**，不是絕對信心度。
> - 無論當日海況多差，輸出中必然有漁場得到 0.8+ 的高分
> - 系統**不具備輸出「今日無適合漁場」的機制**
> - 船東不應僅憑分數絕對值判斷是否出海，應結合安全系統和海況評估
> - 分數 0.90 僅代表「今天這片海域裡最好的地方」，不代表「這裡一定有魚」

### 7.4 熱點提取（NMS + 5 層過濾）

```
候選點過濾：
  1. score ≥ 0.15
  2. 水深 ≥ 200m（遠洋延繩釣最低作業深度）
  3. 不在封閉海域排除區（蘇祿海、爪哇海、黃海...共 14 區）
  4. 不在陸地 bbox 內（除非水深 > 800m）
  5. 物種水深範圍匹配

NMS（非極大值抑制）：
  最小間距 0.5°（~55 km）→ 避免相鄰格點重複推薦

跨物種去重：
  每物種保證最少 3 個配額 → 剩餘按分數全局排名
```

### 7.5 EEZ 地理圍欄

禁漁區排除：自動過濾他國 200 海浬經濟海域。

### 7.6 AIS 競爭密度懲罰

當某漁場已有大量漁船作業 → 自動降分，避免擁擠。

## 九、生態模型系統

### 9.1 NPZ 生態動力模型

**檔案**：`npz_model.py`（281 行）
```
三層簡化海洋食物網：
  dN/dt = -μ_max × N/(N+K_n) × P + remineralization
  dP/dt = +μ_max × N/(N+K_n) × P - grazing × P × Z - mortality_P
  dZ/dt = +grazing × assimilation × P × Z - mortality_Z × Z²

初始條件由 SST → 生長率修正, CHL → P 初始值
模擬 n_days 天後的最終狀態
```

### 9.2 食物鏈預測

**檔案**：`food_chain_predictor.py`（527 行）  
VGPM 模型估算初級生產力 (NPP)：
```
  NPP = 0.66125 × Pb_opt(SST) × E₀/(E₀+4.1) × CHL × Zeu × DL
  Pb_opt = 多項式(SST)  — Behrenfeld & Falkowski 1997
  Zeu = 200/CHL^0.5      — 透光層深度
```

### 9.3 垂直遷移模型 (DVM)

**檔案**：`dvm_model.py`（227 行）  
```
  日間深度 = 溫躍層下方 + 月光修正
  夜間深度 = 表層 + 月相修正
  月光越強 → 夜間仍在較深處（躲光）
```

### 9.4 浮游動物代理

**檔案**：`zooplankton_proxy.py`（271 行）  
```
  Zoo_index = f(CHL, SST, MLD, 緯度, 季節)
  CHL 高 + MLD 淺 + SST 適中 → 浮游動物旺盛
```

### 9.5 ENSO 校準

**檔案**：`enso_calibrator.py`（323 行）  
```
  ONI > +0.5 → El Niño → 黃鰭鮪 HSI -0.05, 大目鮪 -0.08, 鰹魚 -0.03
  ONI < -0.5 → La Niña → +0.03~+0.05
  Species modifier 調整 HSI ±3-12%
```

> **參數來源標註**：
> - ENSO 相位分類（ONI ±0.5 門檻）— [📖 NOAA 標準定義](https://origin.cpc.ncep.noaa.gov/products/analysis_monitoring/ensostuff/ONI_v5.php)
> - 各物種 HSI shift 幅度（-0.03~-0.12）— [🔬 內部設定] 經驗性參數，無文獻直接支持此精確數值
> - 緯度位移率（0.3-1.5°/ONI）— [🔬 內部設定] 基於一般性 ENSO 影響文獻的感性描述，未從特定論文提取數字
> - PDO/IOD 修正 — [📖 Mantua 1997; Saji 1999] 參考文獻已引用，但修正幅度為 [🔬 內部設定]

## 十四、SHAP 可解釋性

**檔案**：`shap_explainer.py`（390 行）

每個推薦漁場都附帶「為什麼推薦這裡」的科學解釋：
```
  使用 SHAP TreeExplainer（對單一樹模型精確、非近似）
  輸出：每個特徵的貢獻值（正=有利，負=不利）
  例如：「此點 SST=27.5°C 貢獻 +0.08, FTLE=高 貢獻 +0.05」
```

> **⚠️ 技術限制說明**：
> SHAP TreeExplainer 解釋的是 **Stacking Ensemble 中的某個基礎樹模型**（RF 或 LightGBM），
> 而非 Ridge meta-learner 融合後的最終輸出。當 Ridge 對某個基礎模型給予低權重時，
> 該模型的 SHAP 值不代表最終推薦的真實決策依據。
> 實際提供的是「某個基礎模型對特徵的敏感度」，而非「系統為什麼做這個推薦」的完整解釋。

## 十七、已知限制與改進路線

本章主動揭露系統目前的已知限制，供技術評估參考。

### 17.1 ML 模型空間泛化能力不足

| 問題 | 詳情 |
|------|------|
| 現象 | 所有 WCPFC 模型的 Spatial CV R² 為負（黃鰭 -0.21, 大目 -0.41） |
| 原因 | 模型記住了訓練資料的地理位置模式，而非學到海洋物理因果關係 |
| 影響 | 在訓練資料未密集覆蓋的海域，ML 預測可能不如直接用 HSI 規則 |
| 已採取措施 | 融合權重從 40:60 調整為 80:20（物理 HSI 主導） |
| 根本解決方案 | 取得真實漁獲回報資料，以時間切割方式重新訓練和驗證 |

### 17.2 合成訓練資料的局限

| 問題 | 詳情 |
|------|------|
| 現象 | 鰹魚/魷魚模型的 R²=0.85-0.92，但這些數字僅代表公式擬合 |
| 原因 | 訓練和驗證都來自同一套合成公式，模型只是在學自己的假設 |
| 影響 | 這些 R² 不代表對真實海洋的預測能力 |
| 解決方案 | 需要真實漁獲資料替換合成資料，重新訓練和驗證 |

### 17.3 WCPFC 資料品質

| 問題 | 詳情 |
|------|------|
| 時間跨度 | 1950-2018 共 70 年，未做 catchability coefficient (q-value) 校正 |
| 影響 | 1950 年和 2018 年的漁具效率、定位精度、報告義務完全不同 |
| Holdout 方式 | 隨機切割，非時間切割，同一地點相鄰季節可能同時在訓練/測試集 |
| 解決方案 | (1) 對 CPUE 做 q-value 標準化 (2) 改用時間切割驗證 |

### 17.4 時間外推驗證缺失

| 問題 | 詳情 |
|------|------|
| 現狀 | 沒有「用 2019 年前資料訓練，2020 年後資料驗證」的外樣本測試 |
| 影響 | 無法量化模型對「未來」的預測能力 |
| 解決方案 | 首批海試漁獲回報後，即可建立時間外推驗證 |

### 17.5 59 維特徵共線性

| 問題 | 詳情 |
|------|------|
| 現象 | SST/T100/MLD/D20/溫躍層深度高度相關 |
| 影響 | 不影響預測精度，但影響 SHAP 特徵重要性的排序可靠性 |
| 解決方案 | 可做 VIF 分析或 PCA 降維（優先級低） |

### 17.6 系統核心價值定位

**目前真正可信賴的能力**：
- ✅ 物理海洋分析層（鋒面、FTLE、渦旋、溫躍層）— 基於物理學公式，可獨立驗證
- ⚠️ HSI 規則模型 — 高斯函數架構合理，但部分參數來自內部觀察（非全部來自已發表文獻）
- ✅ 安全評估系統 — 基於氣象物理
- ⚠️ ML Stacking 預測 — 在已知海域有參考價值，新海域不可靠
- ⚠️ 合成模型 — 僅作為 HSI 的補充加權，不應作為獨立預測依據
- ⚠️ 增量學習 — 目前僅蓄集資料，自動模型替換已停用

> **HSI 參數來源透明度說明**：
> 系統內每個 HSI 參數均已標註來源類型：
> - 🧠 **專家知識**：漁業科學廣泛共識，但無單一引用源
> - 🔬 **內部觀察**：開發過程中從資料分析所得，尚需外部驗證
> - 🔬 **內部設定**：經驗性參數，未經系統性敏感度分析

**取得真實漁獲回報後可達到的能力**：
- 時間外推驗證 R²
- 按海域校準的融合權重
- Catchability 校正後的 CPUE 訓練
- 有監督的增量學習（含 holdout 驗證 + 人工審核）
